# 2026-10-29

## v1.0.7 数据安全修复

**问题 1：并发写盘互相覆盖**
- 后台防抖写入（1s）与删除/收藏触发的同步写入共用同一个 `.tmp` 文件
- 后台写 30MB+ 期间发生同步写，同步写先 rename 成功，后台再把旧快照 rename 上去
- 结果：已删除的记录被写回、刚复制的记录丢失（32MB 数据下 3/3 必现）
- 修复：写盘串行化（`writing` / `dirty`），进行中再有改动只标记 dirty，写完补写最新快照；`saveNow` 不再同步阻塞主进程

**问题 2：数据文件损坏后被空数据覆盖**
- 启动解析失败时用空数据开局，下一次保存即覆盖原文件
- 修复：先改名为 `.corrupt-<时间戳>` 保留；改名也失败则本次运行禁止写盘（`writeBlocked`）；同时校验 `clips` 为数组

**问题 3：退出丢失最近 1 秒的改动**
- 修复：新增 `flushDatabaseSync()`，在 `will-quit` 时用独立的 `.quit.tmp` 同步落盘

**问题 4：v1.0.6 引入的回归 —— 重复复制不置顶**
- 1.0.6 把文本/图片拆成两个 hash，但剪贴板换掉内容时未清空对应 hash
- 「复制图 A → 复制文字 → 再复制图 A」第二次被判为未变化而忽略，表现为"复制图片没记录"
- 修复：剪贴板不再包含某类型时清空该类型 hash

**验证**：隔离 userData + mock electron，旧代码均复现、新代码全通过；已发布 v1.0.7（tag + GitHub Release）

## 已知问题根因：浏览器复制网页图文读不到图片

- Chromium 130（Electron 33）macOS 实现只认 `public.png` / `public.tiff`
- 浏览器选中网页图文复制时，剪贴板只有 `public.html`，图片仅为 `<img src="网址">`
- 决策：**不做**从 HTML 抓图下载（涉及主动联网、内网图失效）

## v1.0.8 持久化迁移到 SQLite

**动机**：JSON 方案每次变更整份重写（31MB+），删除/收藏为同步写，阻塞主进程约 59ms；搜索每次全量扫描两遍（`toLowerCase` 覆盖 1900 万字符），27–41ms。

**注**：3-17 的记忆里记录过"放弃 better-sqlite3（Node 25 + Python 3.14 兼容性问题）"。本次用 npm 预编译包（Node 22.22）+ `electron-rebuild` 成功，未走源码编译。

**方案**
- `database.ts` 重写，对外导出签名一个未改（渲染层、IPC 层零改动）
- 表：`clips` 单表 + `(is_favorite DESC, last_pasted_at DESC)` 排序索引 + `type` 索引
- 全文：FTS5 `trigram`（中文子串匹配），触发器同步；3 字符以上走 FTS，更短回退 `LIKE`
- 写入：INSERT / UPDATE / DELETE 增量执行，WAL 模式
- 首次启动：单事务导入旧 JSON + `INSERT INTO clips_fts(clips_fts) VALUES('optimize')`，成功后 JSON 改名为 `.migrated-<时间戳>`
- 数据库打不开：改名为 `.corrupt-<时间戳>` 保留
- 条数/天数限制在 `saveSettings` 时立即清理（此前需累计 10 次新增）
- 退出：`wal_checkpoint(TRUNCATE)` + `close()`

**构建要点（踩坑记录）**
- `vite.config.ts` 必须把 `better-sqlite3` 设为 `rollupOptions.external`，否则会被打进 bundle，`bindings` 解析不到 `better_sqlite3.node`
- `electron-builder.yml` 需显式打包 `node_modules/better-sqlite3`、`bindings`、`file-uri-to-path`，并 `asarUnpack` 该模块
- 本机 Node ABI 127 / Electron ABI 130，浏览器测试需 `ELECTRON_RUN_AS_NODE=1 /Applications/SnapPaste.app/Contents/MacOS/SnapPaste`；该环境变量常驻会导致 `npx electron` 以纯 Node 模式启动（需 `env -u`）

**实测（真实数据副本 15,394 条）**
- 搜索：2 字 28.7ms（旧 41ms）、3 字以上 0.4–1ms（旧 27–37ms），命中数完全一致
- 删除 0.3ms、收藏 0.1ms（旧 59ms）
- `integrity_check = ok`，重启后计数与收藏一致
- 取舍：db 约 86MB（JSON 31MB），增量主要是 trigram 索引

**未纳入 1.0.8**（仍待修）
- 搜索请求在 `isLoading` 时被丢弃，快速输入可能停在旧结果
- 图片 base64 缓存无上限（`ClipboardItem.tsx` `imageCache`）
- 剪贴板停留图片时每秒重新编码 PNG 算哈希
- 启动时未初始化图片 hash，剪贴板里的图会被再录一次
- 图片路径前缀校验未带路径分隔符
